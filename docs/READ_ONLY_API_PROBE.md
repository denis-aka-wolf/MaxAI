# Проверка read-only API MAX

Документ описывает первоначальный набор API MAX только для чтения, реализованный в `packages/maxai_protocol` и доступный через Windows-приложение `apps/auth_probe`.

Реализация основана на конструкторах payload и методах сервисов, изученных в текущем исходном коде PyMax. PyMax является результатом обратного исследования, а не официальной спецификацией протокола MAX. Каждый метод необходимо дополнительно проверить на реальном аккаунте, прежде чем считать его подтверждённым сервером.

## Реализованные операции

| Операция | Opcode | Payload запроса | Поле ответа |
|---|---:|---|---|
| Снимок профиля | LOGIN / LOGIN2 | Дополнительный запрос не требуется | `profile` |
| Снимок контактов | LOGIN / LOGIN2 | Дополнительный запрос не требуется | `contacts` / `contactInfos` |
| Информация о контактах | 32 | `contactIds: [int]` | `contacts` |
| Список чатов | 53 | `marker: int` | `chats` |
| Информация о чате | 48 | `chatIds: [int]` | `chats` |
| Участники чата | 59 | `type: MEMBER, chatId, marker, count` | `members, marker` |
| История чата | 49 | `chatId, forward, backward, backwardTime, forwardTime, getChat, from, itemType, getMessages, interactive` | `messages` |
| Выборка отдельных сообщений | 71 | `chatId, messageIds: [int]` | `messages` |

Снимки профиля и контактов извлекаются из уже полученного bootstrap-ответа LOGIN/LOGIN2. Дополнительный сетевой запрос для этого не выполняется.

## Важное различие opcode

Opcode 16 (`PROFILE`) используется в изученной реализации PyMax для изменения текущего профиля. Это не операция чтения профиля, поэтому она намеренно исключена из read-only API.

Opcode 36 (`CONTACT_LIST`) присутствует в enum opcode, однако в изученном исходном коде PyMax нет соответствующего payload или метода сервиса для получения списка. Поэтому этот opcode не отправляется до независимого подтверждения схемы запроса и семантики. На данный момент сведения о контактах запрашиваются через opcode 32 с использованием `contactIds`.

## Безопасность и диагностика

- API-слой принимает только RESPONSE-кадры, соответствующие запрошенному opcode.
- Кадры ERROR преобразуются в безопасное исключение; исходный payload сервера не копируется в исключение или диагностический журнал.
- API Probe записывает название операции, время выполнения, количество полученных элементов и безопасные сведения об ошибках.
- Текст сообщений, сведения о контактах, токены и исходные payload ответов в журнал не записываются.
- В этот набор API не входят операции изменения данных.
- Интерфейс предоставляет отдельные кнопки для операций и требует авторизованную сессию.

## Локальная проверка

Из каталога `packages/maxai_protocol`:

```powershell
dart analyze
dart test
```

Из каталога `apps/auth_probe`:

```powershell
flutter analyze
flutter test
```

Для выборки отдельных сообщений (MSG_GET) используются выбранный Chat ID и список Message ID, разделённых запятыми, точками с запятой или пробельными символами. Операция не изменяет данные.

Проверки реального API следует выполнять по одной операции за раз через интерфейс `auth_probe`. Успешный unit-тест подтверждает формирование payload и обработку ответа, но не доступность операции на сервере и не наличие необходимых прав у аккаунта.
